一、系统简介
本发明提供了一种基于应用程序区的通用 Boot 固件升级系统，适配多种嵌入式处理器平台，核心在于通过软件层面的模块化设计，在无需外部烧录工具的前提下完成 Boot 固件的在线升级。系统核心由主升级程序模块、存储区域编程程序模块、底层硬件抽象接口程序模块及 boot 程序存放模块构成，各模块在代码层面解耦且协同完成升级全流程，具体功能如下：
1. 主升级程序模块
作为整个升级系统的核心调度单元，该模块以可执行代码形式部署于嵌入式设备的应用程序区，上电后执行该函数开始进行将新BOOT固件升级到设定的BOOT物理地址区域中的一系列逻辑。 
2. 存储区域编程程序模块
作为升级操作的 “执行单元”，核心负责 Boot 固件存储区域的擦写、校验闭环操作，代码逻辑与主升级程序模块深度联动。该模块接收主升级程序模块的操作指令后，读取代码中预先固化的目标 Boot 存储分区物理地址、存储空间大小、擦写时序等参数，依次执行 “现有 Boot 存储区擦除→待升级镜像分块写入→写入数据完整性校验”；其中擦除操作针对 Flash/EEPROM 等不同存储介质优化了代码层擦除粒度，操作完成后，向主升级程序模块返回执行状态码，供上层判断升级结果。
3. 底层硬件抽象接口程序模块
作为跨平台适配的 “适配层”，核心解决不同嵌入式芯片平台存储操作的兼容性问题，代码核心是对各类芯片非易失性存储器（NVM）的底层操作指令做统一封装。针对不同架构芯片，以及不同厂商芯片在存储擦除、写入、读取时的寄存器配置、时序控制、指令集差异，该模块在代码层抽象出通用标准化接口，向上层存储区域编程程序模块提供统一调用入口，完全屏蔽底层硬件操作差异；开发人员无需修改存储区域编程程序模块核心逻辑，仅需在该模块适配对应芯片的硬件驱动代码，即可实现升级系统跨平台移植，大幅降低适配成本。
4. boot 程序存放模块
通过制作的bin2c工具对需要升级的boot.bin文件进行转换得到的.c文件，其内容为bin文件内容转化为适配flash写入带宽位的十六进制数组内容。
